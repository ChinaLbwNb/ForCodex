# 互动叙事产品方案（独立旁白 + 多角色机制）PRD

## 1. 文档目标
本方案用于解决互动小说、文字冒险中常见的三类问题：

1. 玩家在单一场景反复停留，不知道如何推进剧情。
2. 多角色关系网维护成本高，角色出入场混乱。
3. 剧情节奏失控：该紧张时拖沓、该收束时发散。

本 PRD 将“**独立旁白（Narrator Layer）**”与“**多角色自动调度机制（Multi-Character Orchestration）”联动设计，输出可直接落地到对话生成模块与前端展示层的规则。

---

## 2. 独立旁白（Narrator Layer）

### 2.1 功能定义
独立旁白是多角色对话系统中的**场景组织单元**：

- 不作为人格化角色参与对话。
- 不替代角色台词。
- 仅在需要场景组织、状态交代、节奏控制时出现。

### 2.2 功能目标
独立旁白用于补足“纯对话模式”的结构缺口：

1. **自然过渡**：在转场、进出场、动作变化、异常事件时衔接自然。
2. **稳定节奏**：承载氛围、节拍、剧情钩子，避免对白漂移。
3. **状态可见**：让玩家清晰感知“发生了什么变化”。

### 2.3 旁白触发场景（7 类）

1. **信息交代**：时间、地点、环境、在场人物、基础状态。
2. **角色信息补充**：动作、表情、视线、站位、距离、道具使用。
3. **角色穿插组织**：谁先说、谁打断、谁接话、谁沉默。
4. **氛围调度**：紧张、压迫、冷场、暧昧、危险、异常。
5. **剧情推进**：转场、收束、抛异常、挂钩子。
6. **状态变化**：伤势、物品状态、门锁/灯光/封印变化。
7. **结果反馈**：玩家动作后的可见结果（推门、递信、拔剑、施法等）。

### 2.4 旁白弱化策略
以下场景降低旁白密度：

- **纯双人对话**（用户 + 单角色）且场景稳定。
- **用户明确要求少旁白**（如“只看对话”“少描述”）。
- **单人剧本历史风格不需改动**。

### 2.5 旁白写作规范

1. **客观描写优先**：写可观测事实，不写主观裁定。
2. **侧面呈现情绪**：通过停顿、动作、语速、距离、光影表现情绪。
3. **人称统一**：旁白统一第三人称；涉及玩家时使用“你”。

### 2.6 旁白插入时机

1. 开场前：建场。
2. 角色切换时：组织发言流。
3. 事件发生时：打断/推进。
4. 一轮结束前：收束并挂下一步钩子。

## 3. 多角色机制（Multi-Character Orchestration）

### 3.1 功能目标
系统基于剧本类型、场景内容、世界书命中和玩家指令，自动决定角色出场与退场。
目标不是“所有人都说话”，而是“**当前最该出场的人在场**”。

### 3.2 剧本类型与行为

#### A. 单角色剧本
1. **关闭多角色对话**
   - 主角色：1
   - NPC：0（仅可被旁白提及）
2. **开启多角色对话**
   - 主角色：1（核心）
   - NPC：按场景自动补充

#### B. 多主角色剧本
- 主角色：2~N
- 可继续按规则自动补充 NPC
- 多主角色均有独立发言权重

### 3.3 角色来源

1. **主角色来源**：剧本预设，优先级最高，默认持续在场。
2. **场景+剧情来源**：由场景常识决定（如教室有教授/同学）。
3. **世界书命中来源**：命中角色条目后加入候选池。
4. **玩家指定来源**：玩家点名角色进场/旁听/回应。

### 3.4 自动出场判断链
按顺序执行：

1. **场景成立判断**：先确保场景不“空壳”。
2. **世界书命中判断**：加入强相关角色候选。
3. **剧情推进判断**：需要抛线索/制造冲突时引入角色。
4. **玩家指定进场**：强制满足（除非世界规则冲突）。

### 3.5 角色筛选优先级（进场）
建议优先级：

**玩家指定 > 主角色 > 剧情推进角色 > 世界书强命中角色 > 场景必要角色**

### 3.6 角色退场规则（退场）

退场触发：

1. 场景结束（地点/事件切换）
2. 功能完成（线索已给、任务完成）
3. 优先级挤出（高优先级角色进入）
4. 剧情清场（聚焦核心冲突）
5. 玩家指定退场
6. 世界物理逻辑退场（身份/距离/受伤/召回等）

退场优先级：

**玩家指定退场 > 世界物理逻辑退场 > 剧情清场退场 > 场景结束退场 > 角色功能完成退场 > 优先级挤出退场**

### 3.7 同场人数控制建议
为避免混乱，建议默认阈值：

- 单角色剧本（多角色开启）：**同场详细发言角色 ≤ 3**
- 多主角色剧本：**同场详细发言角色 ≤ 4**
- 超阈值时仅保留“核心发言位”，其余角色转入旁白提及或短反馈。

## 4. 核心聊天展示区（UI 层）

### 4.1 分层展示

1. **旁白层（Narrator）**
   - 样式弱化（灰色/斜体）
   - 独立成段
   - 用于场景、状态、推进

2. **多角色对话层（Character Dialogue）**
   - 头像 + 角色名 + 台词
   - 角色视觉区分明确
   - 尽量只保留台词；动作/神态尽量由旁白承接

3. **用户输入层（Input）**
   - 普通对话输入：自然语言提问/回应
   - 剧情推动输入：`*动作*` 语法（如 `*推开门走出去*`）

### 4.2 输入解析规则

- 命中 `*...*`：作为“剧情推动动作”处理，优先驱动世界状态变化。
- 未命中：作为普通对话处理。
- 无论哪类输入，系统都必须返回“可见后果”（角色反应 + 场景反馈）。

## 5. 后端决策流程（建议）

```text
接收用户输入
 -> 识别输入类型（动作/对话）
 -> 更新短期状态（场景、角色、道具、事件）
 -> 计算角色进场候选（玩家指定/主角色/场景/世界书/剧情）
 -> 进行角色筛选与人数裁剪
 -> 判定旁白触发类型（7类）与插入位置
 -> 生成输出（旁白段 + 角色台词段）
 -> 写回状态（角色在场表、关系网、世界状态、剧情钩子）
```

## 7. 关键验收标准（Acceptance Criteria）

1. **防徘徊**：连续 3 轮无实质推进时，系统必须抛出至少 1 个推进钩子。
2. **可解释出场**：每个新出场角色都能映射到“场景/世界书/剧情/玩家指定”之一。
3. **人数可控**：同场详细发言角色不超过阈值。
4. **结果可见**：玩家每个动作输入都收到明确结果反馈。
5. **节奏可控**：紧张场景的旁白密度高于日常闲聊场景。
6. **偏好可控**：用户设置“少旁白”后，旁白段落占比明显下降。

## 9. 实施优先级建议

### P0（必须）
- 旁白 7 类触发器
- 角色进退场优先级引擎
- 同场人数控制
- `*动作*` 输入解析与结果反馈

### P1（应有）
- 旁白密度可配置（low/medium/high）
- 剧本分型开关（单角关闭/开启多角色）
- 世界书命中解释链路（用于调试）

### P2（增强）
- 节奏模板（悬疑/恋爱/战斗）
- 场景化旁白风格包
- 可视化关系网调试面板
